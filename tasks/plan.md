> 当前实施：见 [阶段 1 数据基础](../docs/阶段1-数据基础.md)，按 S1→S5 逐步验证。它落实 T01–T05；T06 桌面外壳仍独立验收，不把它计入已完成。

日期：2026-09-20。范围：本机独立运行、自己的模型/搜索配置、自动增量更新。状态：AI 功能待实现；按用户要求先完成 TS 工作台及 Node/TS 状态服务基础迁移。没有修改真实数据库或定时任务。

规格：[本地 AI 更新功能规格](../docs/本地AI更新功能规格.md)；执行清单：[todo.md](todo.md)。

## 一句话顺序

**保护数据与副本隔离 → 模型设置 → 一条来源的手动完整流程 → 扩展来源和内推 → 每日自动运行 → 干净电脑分享验收。**

不要先写定时器。可靠性问题必须在可观察、可手动重试的流程里解决，再放到后台运行。

交付证据：两个测试配置相互隔离；不会误连端口上另一份台账；临时旧库迁移前后的公司名、状态、更新时间逐条一致；失败时仍可打开旧副本；现有 70 项测试与新增测试同时通过。

下一批 T04–T06 让完整版和悬浮助手从同一目录服务读数据，旧 315 家公司名称/顺序保持一致，再允许本地新增。模型设置放在这之后，避免先接通 API 却没有安全的数据落点。

## 阶段 A：原应用不退步，数据不串库（T01–T06）

目标：为新增能力提供安全落点，保持已认可 UI。工作在分享仓库，不在日常安装目录直接改动。

- 初始测试使用临时目录和空闲端口。当前 `launcher.py` 只验证应用名，新增实例/配置身份检查后，不复用不同配置的服务，也不强杀占用进程。
- `qiuzhao.db` 的现有业务表和 API 继续兼容；旧数据导入是显式动作，不扫描整个用户目录自动寻找数据库。
- 建立 `catalog.db`，通过可信种子初始化目录。种子不代表岗位当前可投；不重新解释旧投递事实。
- 完整版、悬浮窗切到同一目录读取服务。页面老数组作为过渡种子保留，停止让新采集逻辑写 HTML。新公司顺序由数据库追加序号保证。
- 当前 `test_backend_file_is_unchanged` 是旧 UI-only 任务的文件摘要保护。真正实现后端变更时，须先增加旧接口、状态枚举、事务和拒绝非法请求的契约测试，经审阅再替换该摘要检查，不能直接删测试。

检查点 A：两端目录与状态一致；新旧数据兼容；使用前后无顺序、筛选、导出、保存重试回归。只有临时配置验证完成，仍不切换用户日常安装。

## 阶段 B：模型设置能用、能失败、能保护密钥（T07–T08）

目标：设置页可填写脱敏求职偏好、模型连接信息并测试，重开仍生效。密钥存 Windows 当前用户凭据存储，不在源码、设置 JSON、日志或浏览器 localStorage。

先支持一个明确的云模型协议，允许用户配置地址和模型；接入前固定支持范围。错误密钥、模型不存在、超时、限流、余额不足和不兼容输出分别显示可操作的原因。不自动买额度，不假设网页聊天会员就是 API 额度。

无模型配置时，原台账功能仍可用；“连接成功”只证明连接，不代表岗位判断准确。Ollama 在同样接口和测试契约下后续接入，不阻挡第一条云模型路径。

检查点 B：真实密钥只由用户在本机设置页输入；模拟错误路径必须通过，允许后才做最小真实连接调用。

## 阶段 C：先跑通一条真实来源的手动完整流程（T09–T12）

目标：点击检查 → 官方页面 → 结构化候选 → 原文证据 → 去重/规则 → 差异预览 → 用户接纳 → 两端看见新增。

先做无需登录的公开来源。稳定公开 HTML 或明确可用接口优先，动态网页/验证码先记为受限，不先搭任意浏览器操控 Agent。提取模块和联网模块可用离线样本独立测，但不能用离线通过代替真实验收。

批次状态：排队、运行、部分完成、完成、失败、取消/需配置。预览与入库分离，入库原子且幂等；重复点击不重复新增。模型只提交候选，不能直接写库或调用系统命令。

公司级旧进度不继承到新岗位，也不因此屏蔽同公司新岗位。第一版保留公司级记录，不把岗位级投递管理捆绑进来。岗位首次发现与岗位发布日期分开；页面未提及的要求就是未知。变化记录保存证据与前后值，失败不清空旧目录。

检查点 C：至少 3 家真实、可访问官方来源手动跑通；同一批次重复接纳不增行；中断后可恢复；更新时个人状态仍可正常保存。此时才可称“接模型后的岗位更新流程可用”。

## 阶段 D：从关注清单扩到发现新公司（T13–T14）

目标：不是仅复查 315 家，而是通过关键词和时间范围发现清单外机会；同时维护公开内推线索。

先增加一个搜索提供者适配器。默认路线是 Tavily，但实际可用性、预算和中文招聘覆盖须在 T13 前核对；可替换供应商，不改变后续候选/证据/去重流程。无搜索配置时清晰标明仅定向检查。

收集分两条队列：已有官方来源复核 + 新来源探索。24 小时不足再扩 7/30 天，记录真实覆盖，不声称穷尽全网。相似职位不能仅凭公司/标题合并，多城市与岗位 ID 按官方事实处理。

内推记录严格按公司/批次绑定。来源声称有效仍为未实测；无法公开获取的说明需本人联系，不自动私聊。

检查点 D：扩到约 20 家、至少 3 类来源；报告访问成功/受限/失败比例、误收与漏收样本、推荐精确率，不以收录数量替代质量。

## 阶段 E：最后加每天自动运行（T15–T17）

目标：手动和计划任务调用同一 worker；开关、预算、时区、补跑、失败可见。

- 用户显式开启后才注册 Windows 当前用户任务。程序界面关闭不影响 worker；用户注销、关机时不承诺运行。
- 时区独立保存，默认建议由用户确认；悉尼与北京时间不同，夏令时切换须测。后台短周期检查到期状态，说明可有调度延迟。
- 同一配置加锁，持久化当天运行记录；重启补跑一次，不能重复补过去多天。异常退出用租约恢复，不永久卡在运行中。
- 默认自动采集到待核验区；通过验收后可启用“可信来源合格新增自动追加”。未知毕业窗口、可疑来源、官方关闭不明确的记录不能偷偷升级为可信推荐。
- 同时限制运行时长、每源请求量、模型调用量与日额度；重试计入预算。额度未配置时使用保守上限，真实付费前明确展示。
- 完全失败与真正零新增分开。应用内显示最近成功时间、失败原因、下一次检查时间以及重试入口。

检查点 E：冻结时钟测试覆盖夏令时、跨日、离线恢复、并发触发、异常退出和额度耗尽；短间隔真实计划任务验证成功后，再观察至少两次计划触发并确认无重复。不能用“已注册任务”冒充“已稳定运行”。

## 阶段 F：别人下载后可独立使用（T18）

目标：干净 Windows 用户/机器完成安装、配置、采集、重开与程序升级。每人数据独立，无维护者凭据，不依赖 Codex 特殊路径或打包前的 vendor 文件。

代码更新和岗位更新分离。先保留人工 Git 更新和有文档的重启流程，不做自动强制 `git pull`、覆盖工作区或执行未审核更新。程序版本和数据库 schema 版本不兼容时明确拒绝启动并提供恢复指引。

最后才决定是否切换维护者的真实日常应用；切换前先备份并核验，旧 Codex 每日任务要显式调整为不重复写同一套资料，但本轮不修改它。

检查点 F：新增用户从空白进度开始；原用户更新后状态完整；API Key 和数据库不在 Git；卸载后台计划任务后不再运行；已知权限/依赖问题记录到安装文档。

## 评测与质量门槛

拟建立 60 条标注用例：20 条明确匹配、10 条硬性不符、10 条条件未知/受限、8 条重复/多城市、6 条关闭/异常、6 条恶意内容/异常结构。40 条开发、20 条冻结验收，分层划分；用例文件记录原始来源或“合成”，数据版本和预期结果。不是已完成的数据集。

每次阶段验收报告：现有回归、新增单测、固定集结果、真实运行范围、失败样本、来源覆盖、实际消耗和未闭环风险。

硬门槛先于模型平均分：进度零误改、重复零新增、网络错误零误下架、所有推荐可追溯、密钥不泄露。推荐精确率目标至少 95%，同时单独报告召回/不确定比例；20 家试点之外不宣称总体覆盖率。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 副本误连原服务 | 配置身份与端口检查；开发仅临时目录 |
| 脱离 HTML 后两端目录不一致 | 同一目录服务，先兼容迁移再撤旧路径 |
| 模型/搜索成本失控 | 有界运行、预算预留、重试计费、缓存和可取消 |
| 页面改版/访问受限 | 每源状态、适配器样本、降级待核验，不误下架 |
| 网页诱导执行/内网访问 | 内容视为数据；无任意工具执行；抓取地址/重定向校验 |
| 迁移丢记录或更新覆盖 | 一致性备份、逐条比对、失败不切换、个人库与采集分离 |
| 计划任务重复或漏跑 | 锁、日键、租约、补跑、持久化运行记录 |
| 旧自动化与新采集器双写 | 正式切换时单独确认任务职责；新采集不写 HTML |
