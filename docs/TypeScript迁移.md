# TypeScript 工程迁移

2026-09-20，响应「使用 TS，不再把所有逻辑堆在 HTML」的技术选择。

## 决策与范围

- 保留已认可的薄荷石墨界面，不引入一次性重做 UI 的风险。
- 使用 Vite + 严格 TypeScript 模块；不为迁移额外引入 React 等视图框架。
- 后端使用 Node.js 24.14+ / TypeScript / SQLite，保留状态接口的请求与响应格式。
- 业务类型、公司目录、持久化、展示与事件分别拆分；不用 `any`、`@ts-nocheck` 冒充 TS 迁移。
- HTML/CSS 仍是必要的浏览器视图文件，不再包含目录和内联业务脚本。
- 旧 Python / HTML 版暂留作兼容回退；本机已安装版不覆盖。
- 桌面贴边窗、AI 搜索更新、模型配置、定时任务分别验收，不把基础迁移称为这些功能已实现。

## 第一阶段验收

1. 315 家公司和顺序完全一致，既有新增日期不变。
2. TS 工作台搜索、组合筛选、分组、详情、主题、导出可用。
3. Node 后端能存储、重启读取并备份 SQLite 状态；非法写入被拒绝。
4. 源码与用户数据分离，新版默认独立空白资料目录及端口 18765，不读取旧版个人数据。
5. 严格类型检查、构建、新版测试与旧版回归分别执行；浏览器验证新版实际链路。

## 威胁边界

本机 HTTP 请求不可信。继续限制 loopback、Host、Origin 和写入令牌；参数化 SQL、长度限制、静态文件白名单。网页输出转义，数据库与日志不加入 Git。此阶段不调用模型、不发求职消息、不注册系统任务。

## 后续

先打通 TS 工作台，再迁移桌面桥接与窗口行为；通过验收后才替换桌面入口。原先本地 AI 更新计划保留，但新增实现改用 TS 模块；不再新增 Python 业务层。

技术依据：[Vite 模块入口](https://vite.dev/guide/)、[TypeScript strict](https://www.typescriptlang.org/tsconfig/strict.html)、[Node SQLite](https://nodejs.org/api/sqlite.html)。Node 24 的 SQLite API 仍有实验性提示，因此将其封装在独立存储模块，锁定运行版本并测试备份/重启，不宣称已验证正式安装包。

## 本次实现

- `src/client/main.ts` 负责视图与事件；`selectors.ts` 负责搜索、组合筛选、分组和排序；`progress.ts` 管理有序保存、失败保留和刷新竞争；`api.ts` 校验响应并在本机服务重启后刷新写入令牌。
- `src/server/http.ts` 提供本机接口和静态资源；`store.ts` 封装 SQLite；`main.ts` 使用独立预览资料和端口，拒绝直接使用旧 `QiuzhaoLedger` 路径或 18763 端口。路径保护不是正式迁移器，未处理所有别名/链接场景，勿手动指向日常库。
- `src/shared/catalog.ts` 保存公共公司目录、性质与新增日期；`types.ts` 定义明确状态、目录字段和接口数据类型。
- `web/index.html` 只保留页面结构与模块入口。CSS 保持原视觉，业务脚本编译为独立资源；不是只把 HTML 改扩展名。
- 新版个人数据默认放在 `%LOCALAPPDATA%\XiaozhaoGaogaoshou\profiles\typescript-preview\`，不在源码仓库中。
