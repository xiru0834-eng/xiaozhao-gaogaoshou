# 邮箱日程助手：第一版实现与验收

日期：2026-09-20。目标：QQ、个人 Outlook/Hotmail、学校 Microsoft 365 与本机模型服务、待确认队列、日历形成真实可执行的代码链路。不是连接按钮演示。

## 当前可用路径

打开 TypeScript 工作台 `http://127.0.0.1:18765/#schedules` → **邮件待确认**。

1. 先在“模型设置”保存自己的 OpenAI 兼容接口，并测试连接。
2. 展开“邮箱连接与隐私设置”。QQ 填 IMAP 授权码；Outlook 选择个人或学校账号，填写自己注册的应用 Client ID 后，在微软官方页面登录。
3. 独立勾选“允许发送招聘邮件正文给当前模型服务”。更换模型服务地址后原授权失效。未授权仍可同步到本机，但不调用模型。
4. “同步并分析”读取收件箱近 30 天最近 100 封，标题规则发现招聘通知；每轮分析最多 3 封，其他保留在待分析列表。也可先粘贴一封通知，不连接邮箱。
5. 模型返回字段、原文引用和不确定项。右侧编辑公司、岗位、日期、时区等，核对后**确认写入日历**。
6. 可显式开启运行期间每 10 分钟同步；默认关闭，软件关闭后不运行，每 UTC 日最多 30 次分析尝试。失败不自动重试已失败的模型任务。

**没有把登录成功当作授权上传私人邮件，也没有把模型预测当作已确认的面试。**

## 本版与完整规划的差异

| 范围 | 本版实现 | 尚未完成 |
|---|---|---|
| 邮箱 | QQ IMAP 只读；个人/学校 Outlook 独立授权路径，可同时保留多个账户 | 三类真实账号授权试点 |
| Outlook 登录 | MSAL 官方设备代码流，无 Client Secret；个人 consumers、学校 organizations | 原规划的浏览器 PKCE 回调；学校租户可能禁止设备代码流，需管理员批准或后续 PKCE |
| 同步 | 近 30 天最近 100 封、有上限提示、持久化内容指纹去重 | UID/Graph delta 增量游标、更多文件夹、完整历史回补 |
| 邮件分析 | 当前模型真实适配器调用，JSON/日期/时区/证据/链接校验；无工具权限 | 真实模型 100 封固定集及质量门槛验收，不能声称准确率 95% |
| 入历 | 新的明确笔试/面试通知，人审后入历；跨库恢复与回执防重复 | 截止日/时间窗口的专用日历类型；自动匹配改期/取消 |
| 疑点 | 缺日期/时区保留空值；附件、正文截断明确警告；改期/取消/截止/窗口引导到日历手动处理 | 附件与 ICS 解析；多场次分解 |
| 自动 | 运行期 10 分钟定时、日预算持久化、进程内互斥、单 profile 锁 | 系统常驻、关机补跑、原生小窗待确认徽标 |
| 数据保护 | DPAPI CurrentUser 隔离加密原文与邮箱凭据；本机 SQLite 保存提取后的字段；清理保留去重墓碑 | 原文按天自动清理、邮件库自动备份/独立导出 |

重要限制：标题过滤可能漏掉不含关键词的通知；达到 100 封上限也可能遗漏。**这版不能替代检查原邮箱**。不会偷偷读取原生旧版的密钥，也不会把旧版投递记录迁移到 TS 预览。

## 功能与非功能验收

- 不经人审不写日历；缺失时间不得猜测默认值直接入历。
- 邮件内容只当数据，HTML 不渲染、远程图片不加载、链接不自动访问。
- 模型返回引用必须逐字出现在原文，链接必须来自原文；无效 JSON/日期/时区/截断输出不得入历。
- 只有已授权的当前模型地址才能接收私人邮件。模型服务每分钟原有 6 次上限继续生效。
- QQ 使用 readOnly 打开 INBOX，不调用发送、删除、移动或已读标记 API。授权码本身可能有更大权限，但应用只读使用。
- Outlook 只请求委托 Mail.Read（及 MSAL 默认身份/离线会话范围），不申请 Mail.Send、Mail.ReadWrite 或日历写权限。本机日历不是 Outlook Calendar。
- 所有邮件 API 需要本机会话 token + profile；跨站 Origin/Host 请求拒绝。凭据不返回浏览器列表、不进日志、Git 或导出。
- 模型失败保留待处理记录；重复确认不重复入历。日历已经提交、邮件状态没写完时，重启利用相同回执恢复，不覆盖后续手动编辑。
- 清理已处理邮件保留指纹墓碑；重新同步同一封邮件不复活为新候选。同公司同类型同一时刻的既有日程拒绝重复新增。
- 每次同步、分析有状态和错误文字。定时与人工同步互斥，网络请求有超时及响应大小限制。

## 实现边界

- `src/shared/mail-contract.ts`：邮件/模型输出/候选状态。
- `src/server/mail-analysis.ts`：惰性文本清洗、受约束提示词、证据与时间验证。
- `src/server/mail-store.ts`：独立 mail.db、加密原文、账户、分析授权、日预算、去重与确认意图。
- `src/server/mail-service.ts`：只经授权调用 ModelService、确认事务协调和恢复。
- `src/server/mail-providers.ts`：QQ/Outlook 适配、授权与续期。
- `src/server/mail-api.ts`：同步/分析作业、10 分钟可选轮询、生命周期。
- `src/client/mail.ts` / `mail.css`：日历内入口、连接、授权、原文核对、编辑入历。

数据链路：

```text
QQ / Outlook / 粘贴通知
  → 只读获取 + 本机去重 + 加密原文
  → 当前模型（需独立授权）
  → JSON / 引用 / 时间校验
  → 待核对，不自动改日历
  → 用户修改并确认
  → mail.db 确认意图
  → schedules.db 日程 + 回执（同一事务）
  → mail.db 已入历（可崩溃恢复）
```

## 接下来真实验收需要的输入

1. 用户在软件里保存模型接口/API Key，不在聊天中提供。
2. QQ 在本机输入 IMAP 授权码；Outlook 使用自己的应用注册 Client ID，完成官方授权。应用支持个人账号与多租户，公共客户端流开启；若学校拒绝授权，不绕过策略。
3. 用合成通知先测试真实模型，再经独立授权选择少量真实招聘通知核对字段、时区和入历结果。
4. 最后做 100 封冻结样例（模板分组的开发/留出集）和两次真实同步；质量门槛未过前保持人审，不开启自动入历。
