# 校招高高手 × 拾知 · 使用指南

当前产品整合校招工作台、面试陪练和普通聊天，支持 Windows Electron 桌面版与源码网页版。个人投递、练习与会话保存在本机。

## 选择入口

| 入口 | 启动与配置 | 数据位置 |
| --- | --- | --- |
| 完整桌面版 | 安装后打开「校招高手」；[安装与模型配置](../products/shizhi-desktop/README.zh.md) | `%APPDATA%\XiaozhaoShizhi` |
| 源码融合版 | 根目录安装依赖后运行 `npm start`；[启动与语音配置](../products/shizhi-interview/README.zh.md) | `products/shizhi-interview/.dsh-home`，可通过 `DSH_HOME` 指定 |
| 独立 TypeScript 工作台 | `npm run build` 后 `npm run start:workbench`，见下文 | 独立的 TypeScript profile |
| Python 兼容工具与桌宠 | [legacy-desktop 使用说明](../products/legacy-desktop/README.md) | 保留旧数据路径或明确配置的 `dataDir` |

桌面安装包内置运行环境；Git 仓库提供源码和构建脚本，不会自动把已有网页版资料或密钥导入桌面版。需要完整校招与面试体验时选择前两种入口。顶部 **设置 → 通用设置 → 外观** 控制整个融合界面的明暗与跟随系统；历史会话从顶部打开。

以下章节说明独立工作台的数据、模型与旧资料导入，不替代融合版和 Electron 的配置说明。

## 独立 TypeScript 工作台启动

需要 Node.js **24.14 或更高的 24.x** 和 npm。在仓库根目录运行：

```powershell
npm ci
npm run build
npm run start:workbench
```

打开 **http://127.0.0.1:18765/**。这是独立预览，不会替换桌面图标，也不会读取原台账的个人记录。

- 资料位置：`%LOCALAPPDATA%\XiaozhaoGaogaoshou\profiles\typescript-preview\`；初次为空白进度，以原 315 家公司初始化独立目录库，后续追加可直接刷新查看。
- 请勿把测试进度当作日常记录。显式导入和桌面接入已在本机验收；每位使用者仍须备份并迁移自己的资料，不会因拉取代码自动更换正式入口。
- Node 24 的 SQLite 模块会显示实验性提示；当前已做本机测试，未做干净机器安装包验收。
- 此处说明独立工作台；默认 `npm start` 启动包含面试陪练的融合版，见[融合版说明](../products/shizhi-interview/README.zh.md)。改代码后需重新构建并重启对应服务。
- Git 更新只更新源码与公共目录种子，不等于自动搜索岗位。AI 接入和每日采集见 [后续计划](../tasks/plan.md)。

```text
src/client/   页面交互、筛选排序、保存队列、接口调用、导出、样式
src/server/   本机 HTTP 服务、SQLite 存储、备份、启动入口
src/shared/   公司目录、状态及公共数据类型
web/          页面结构与模块入口；没有内联业务脚本
tests/        TypeScript 单测及接口、持久化测试
docs/         迁移说明与功能规格
```

运行检查：

```powershell
npm test
npm run build
npm run test:legacy
```

前两条验证新版；最后一条验证仍保留的旧版。测试使用临时数据库。迁移范围、测试证据与剩余事项见 [TypeScript 迁移](TypeScript迁移.md)。

## 模型设置（TypeScript 版）

独立工作台的模型设置可配置一个自定义 **OpenAI 兼容 Chat Completions** 接口：填写公网 HTTPS Base URL、模型 ID、API Key，保存后点击「测试连接」，或输入一句话「发送并生成」。兼容的完整 `/chat/completions` 地址会自动规范化。模型名称以服务商控制台为准。

- 保存只写本机，不调用模型；测试/生成会向你指定的服务发送内容，可能产生费用，不自动重试。
- API Key 由 Windows 当前用户 DPAPI 加密，保存在资料目录的 `model-settings.json`，不回显、不进 Git 或数据库导出；换电脑需重填。修改服务地址须重新输入 Key。
- 可设置超时、输出上限和 Token 参数类型，可停止请求；停止不保证服务商免计费。只发送固定测试文本或你输入的文本，不自动附带简历和台账。
- 目前只支持非流式文本，不支持内网/Ollama、系统代理、自签证书及 Responses 协议；未配置模型也能使用台账。
- 这不是每日搜岗功能。代码已通过本机合成服务与 Windows 加密测试，**用户真实接口仍需在页面完成一次生成验收**。

需求、可行性、验收标准、测试结果与限制见 [模型设置说明](模型设置-需求与验收.md)。旧 Python / 桌面贴边助手尚未接入这一功能，勿在 `18763` 寻找新版模型设置。

## 独立资料与旧进度导入

每份 TypeScript 资料包含 `runtime.db`（稳定身份与运行锁）、`qiuzhao.db`（投递进度）、`catalog.db`（可追加公司目录）和 `backups/`。程序启动生成当日一致性备份；页面也可分别下载进度库和目录库。备份用于保全数据，不代表已实现一键整库恢复。

源码更新不覆盖资料。目录种子只追加缺少的公司，不重排或覆盖既有行。动态追加接口及字段见 [阶段 1 规格](阶段1-数据基础.md)；阶段 1 的独立资料边界继续保留；当前另有受限手动采集和显式开启的运行期每日更新，范围见[实现与验收](每日更新与角色来信-实现与验收.md)。

导入是显式、离线操作：先停止目标资料的服务，再运行以下命令。`--source` 必须是旧 `qiuzhao.db` 的绝对路径；`--data-dir` 指向源码之外的新资料目录。示例路径需要替换为自己的文件，不要直接照抄来源路径。

```powershell
npm run build
npm run profile:import -- --source "C:\迁移资料\旧库.db" --data-dir "$env:LOCALAPPDATA\XiaozhaoGaogaoshou\profiles\my-ledger"
npm run start:workbench -- --data-dir "$env:LOCALAPPDATA\XiaozhaoGaogaoshou\profiles\my-ledger" --port 18765
```

导入只读取源库，经一致性快照验证后，事务写入全部状态及原时间；目标存在任何进度或导入回执都会拒绝。没有强制覆盖参数。失败可查看命令错误并保留源库；不要删除已使用的目标库来重试。需要重做时选择另一个新资料目录。

同一资料不能同时运行两个服务或导入进程，异常退出后锁可自动释放；端口冲突会明确失败，不接管其他进程。拒绝把资料放在源码、旧 `QiuzhaoLedger` 路径及其目录联接中。旧网页在端口切换到另一份资料时会停止读写，须重新打开页面。

阶段 1 已通过本机 31 项 TS 测试、70 项旧版回归及真实浏览器检查；完整范围与限制见 [验收记录](阶段1-数据基础.md#2026-09-20-实际验收结果)。

## 已有功能

- 公司搜索，性质、行业、投递状态等组合筛选；最近新增、截止日期分组与排序。
- 推荐码复制、招聘入口、详情、明暗主题和紧凑视图。
- SQLite 保存进度，支持「无合适岗位」；提供导出和备份入口。
- 可选桌面悬浮助手：贴边收起、固定、切换下一家、与完整版共享本机进度。
- 悬浮助手的今日计数记录状态变更，不代表已在招聘官网完成真实投递。

初始目录包含 315 家公司，是 2026-09-20 的分享快照，不是 315 个已核实仍开放的岗位。内推码为历史公开线索，未在本次分享时逐条实测，须核对公司、批次、届别和有效期。本应用不会自动投递、读取短信或联系招聘人员。现已支持笔试/面试日历、求职任务及邮件人工核对入历，见[任务说明](邮件转求职任务-实现与验收.md)。

## 获取后续更新

维护者把新版本提交并推送后，在这个仓库目录中执行：

```powershell
git status --short
git pull --ff-only
```

若有本地代码改动或提示冲突，请停止并联系维护者，不要使用强制覆盖命令。`--ff-only` 在历史发生分叉时拒绝合并，见 [Git 官方说明](https://git-scm.com/docs/git-pull)。

更新前先通过应用导出一份数据库备份到仓库之外，并确认页面显示保存完成。关闭页面不等于后台服务退出。TypeScript 版更新后执行 `npm ci`、`npm run build`，在原服务终端按 Ctrl+C 后重新 `npm run start:workbench`。旧 Python 版更新也需要重启对应服务；不要删除数据库来解决启动问题。

源码更新不是实时推送：维护者发布后，使用者主动拉取。新版每日更新须在软件中单独配置时间、模型、额度并启用，后台停止时不会自行唤起；这和 Git 拉取是两种不同的更新。

## 个人数据与使用边界

- 各入口首次使用自己的资料时会创建空白进度，不会获得维护者的投递记录。
- 各资料的 `runtime.db`、`qiuzhao.db`、`catalog.db`、备份、日志、浏览器缓存、窗口设置和今日计数均不进入 Git。普通拉取更新不替换这些文件；`.gitignore` 不是数据备份，也不能阻止人为强制添加文件。
- 不要把整个已使用的应用目录打包发给别人；分享仓库链接即可。不要在 Issues、截图或日志中泄露简历、电话、身份证、验证码和个人申请链接。
- 旧 Python 版同一台电脑只运行一个安装目录，固定使用端口 18763，另一份副本可能复用旧服务。TypeScript 预览使用独立端口 18765 和独立资料；两者不共享进度。
- 不要把本地端口暴露到公网或做端口转发；这不是具备多用户认证的服务器产品。
- 岗位和内推信息仅供查找线索，填表须使用自己的真实资料；最终结果以招聘官网为准。

旧版测试需要 Git，以及 PATH 中的 Node.js（用于运行页面实际 JavaScript；仅旧版应用运行本身不需要 Node）。新版启动和测试都需要上述 Node 24.x 环境。

```powershell
npm run test:legacy
```

测试使用临时数据库和隔离端口，不应启动或改写日常台账。开发预览可运行 `python products/legacy-desktop/scripts/preview_isolated.py --port 18764 --seconds 600`，然后访问 `http://127.0.0.1:18764/`；预览数据退出后丢弃。

旧版文件保留作为迁移对照和回退：`products/legacy-desktop/` 中的页面与模块，以及其 `tests/` 目录。新业务在 `src/` 下用 TS 实现；不要将新版目录改动同时回写旧 HTML，避免双源双写。

发布范围与验证记录见 [共享与更新说明](共享与更新说明.md)。本仓库暂未选择公开开源许可证；第三方依赖仍遵守各自许可证。
