实际预览资料当前无邮箱账户、无模型配置；邮件自动分析和每日更新均未启用。本次不会替用户配置或开启。

## 1. 现在实现了什么

入口：**面试日程 → 求职任务**，或 **面试日程 → 邮件待确认**。

1. 手动记录面试、笔试、测评，支持参加、完成、预约和提交材料。无模型时也能管理任务；支持编辑、进行中、完成、重新打开、取消、软删除及恢复。
2. 时间明确分为固定安排、截止、有效窗口和时间待定。只有日期不会补成 23:59；没有时区不会默认北京时间；招聘方安排与自己的计划时间分开。
3. 邮件模型分析可返回 0～8 个事项。每项展示任务内容、时间语义、逐字证据、待核实点，用户可修改后确认，也可勾选批量确认、只处理部分、逐项忽略。
4. 原邮件入口使用本地 LINK 引用，模型不能凭空生成入口 URL。发送前隐藏链接原文和常见邮箱、手机号、证件号、密钥／验证码；原文只在本机核对界面显示。不声称规则能识别所有敏感内容，仍须用户单独授权模型分析。
5. 来源、分析版本和确认批次持久化。重复点击、网络中断后重试不会多建任务；任务事务成功而邮件确认回写失败时，可从持久回执恢复，不覆盖后续人工修改。
6. 改期／取消必须选择原任务及版本；重复通知可仅关联来源，不改变原任务内容。旧版 `events` 的复杂变更仍通过原日历编辑，不做静默转换。
7. 新任务直接投影到现有月历、当天安排和全部列表；截止、开放窗口与个人计划使用不同标记。**不再往旧 `events` 复制一份任务**。无时区的精确时间保留在待定列表；日期标记不等于定时提醒。
8. 任务列表支持搜索、类型／进度筛选、分页，编辑器支持准备清单和经用户点击才打开的通知入口。保留既有薄荷石墨与五皮肤设计；窄屏筛选完整显示，编辑器底部保留保存入口。

## 2. 代码与数据边界

| 职责 | 实际文件／接口 |
|---|---|
| 任务类型、时间精度、DST 校验、标记投影 | `src/shared/recruitment-task-contract.ts` |
| 主记录、来源、历史、修订号与幂等回执 | `src/server/recruitment-task-store.ts` |
| 任务列表、详情、命令、时间线 | `GET /api/recruitment-tasks`、`GET /api/recruitment-tasks/:id`、`POST /api/recruitment-task-commands`、`GET /api/recruitment-timeline` |
| 邮件预处理、模型 JSON 及证据校验 | `src/server/mail-task-analysis.ts` |
| 来源版本、单项／批次确认、跨库恢复 | `src/server/mail-task-service.ts`、`src/server/mail-store.ts` |
| 邮件 API | 复用受保护的 `/api/mail`，新增 `analyzeTasks`、`manualTask`、`confirmTasks`、`ignoreTask`、`recoverTasks` 操作 |
| 核对、编辑、列表与日历 | `mail-task-review.ts`、`recruitment-task-form.ts`、`recruitment-tasks.ts`、`schedules.ts` |

实现取舍：复用项目现有 `/api/mail` 命令协议，未另建设计草案中的多个同义 REST 入口；任务命令使用 `requestId + operations`。客户端日历组合旧事件和新任务，复用共享投影函数；联合时间线 API 也提供同一计算结果。没有另建 tasks.db。

`schedules.db` 与 `mail.db` 均扩展到 schema 2。遇到 schema 1 时，先生成独立 SQLite 快照并检查完整性，再在事务内新增表；原事件、邮件与旧回执不改写。拒绝更新版本的库。旧程序不能直接读 schema 2，不能把 `user_version` 改回去冒充回退。

跨库确认顺序：

```text
用户核对 → 校验来源版本、候选状态及目标修订号
         → mail.db 保存确认意图
         → schedules.db 原子保存任务、来源、历史、回执
         → mail.db 回写逐项状态
```

中断后重放同一个请求；回执内容不一致、目标已变化或事项已处理则拒绝。任务保存成功但回写失败保留意图；“核对保存结果”及服务重启可恢复。一次批次任一操作失败，目标库整批回滚；不是跨两个 WAL 文件假装一个事务。

所有新 API 都复用本机 token、profile、Origin／Host 检查。模型没有任务写入工具。证据必须是对应邮件处理文本的子串；年份或时刻无法与时间证据对应时退回时间待定。此为结构与来源校验，不是对模型语义正确性的数学证明。
