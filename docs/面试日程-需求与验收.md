# 面试日程：需求、设计与验收

状态：用户已确认月历左侧、当天安排右侧及自行设计实现；2026-09-20 已实现并完成隔离环境浏览器验收，已部署到本机 TypeScript 服务。

## 目标与已确认范围

在“校招高高手”内提供独立的笔试、面试备忘录模块。完整版支持月历与整体列表，小窗显示今日／接下来的日程并提供入口。支持新增、编辑、完成、取消和删除，只在本机保存，不修改公司排列与已有投递状态。

延续既有“薄荷石墨·轻量工作台”：清爽、精致、少装饰，兼容明暗主题。采用真实可交互 UI，不将界面图片作为最终实现。

## 场景与交互

1. 收到面试通知：新增公司、岗位、笔试／面试类型、轮次、日期时间、时区、会议链接／地点及备注。
2. 查看安排：月历标出事件类型与数量；点击日期显示当日日程；点击事件进入详情。
3. 查看全部：列表按今天、接下来、已结束分组，支持公司搜索及类型／状态过滤；没有日期的待定安排单列，不伪造时间。
4. 准备与复盘：准备清单可勾选，复盘备注独立于基本资料；改期编辑原事件，避免制造重复安排。
5. 状态：待参加、已完成、已取消。不因时间过去自动推断已参加，也不自动把公司的投递状态改为“面试”。
6. 小窗：轻量入口展示下一场；无日程时给出新增入口，不常驻展开大日历挤占公司列表。

## 时间规则（建议默认，用户可修改）

- 默认以 Asia/Shanghai 录入，同时展示 Australia/Sydney 对应时间。
- 明确显示日期、时间和时区，不用固定时差计算悉尼夏令时。
- 保存绝对时间和原始时区；不同日期的时区换算需通过测试。
- 结束时间可选，但填写后必须晚于开始；待定日期或时间应显式表达。
- 本轮不承诺系统关闭后闹钟、短信通知或日历第三方同步。这些不是本地日程显示的同义功能。

## 数据与技术边界

当前仓库为 TypeScript + Vite 客户端、Node HTTP/SQLite 服务；桌面小窗仍是 Python WebView2。当前源码未发现可复用的日程模块，需新增。

- TypeScript 中新增独立的日程契约、服务存储、客户端视图和测试，复用已有 session/profile 防护与主题令牌。
- 日程是个人数据，不能写入公共 catalog，也不能进入 Git。优先独立 schedules.db，不改 applications 表；具体 schema 在实施计划确认后建立。
- 写入成功后才显示成功。失败保留表单内容，重试不得生成重复日程。
- 编辑需检查版本，防止多窗口静默覆盖；删除需确认。
- 小窗通过已有本地服务边界读取概览，不建立另一份独立日程数据。
- 当前有旧 Python 安装版与 TS 运行版并存的历史；实施前必须确认实际用户入口，避免功能只存在于开发预览。
- 保留当前 tasks/plan.md、tasks/todo.md 的无关未提交改动。

## 验收标准

- 新增事件后，日历日期、当天列表和整体列表一致；重开服务后仍存在。
- 同一天多场事件不遮挡，按开始时间排序；空日期可直接新增。
- 完成、取消、改期及删除在各视图同步，不改变公司投递状态或每日投递计数。
- 覆盖北京时间／悉尼夏令时切换、跨日、跨月、闰日和非法日期。
- 覆盖重复保存、版本冲突、磁盘错误、异常响应，失败不假报成功。
- 输入显示使用转义，外链只允许合法 HTTP(S)；不执行备注里的 HTML。
- 真实浏览器检查桌面与窄屏、明暗主题、表单键盘路径、无控制台异常。
- 原有全部回归测试、构建与数据库完整性检查通过。

## 工程约定与命令

沿用现有格式：客户端模块导出 mount 函数；共享契约位于 src/shared；服务位于 src/server；客户端位于 src/client；测试位于 tests。

```ts
export type ScheduleKind = "written" | "interview";
export type ScheduleStatus = "planned" | "completed" | "cancelled";
```

构建：`npm run build`

TS 测试：`npm test`

桌面回归：`python -X utf8 -m unittest -q`

必须：先失败测试、后实现，数据写入确认，记录实际测试结果。

超出范围需另行确认：系统通知机制或第三方日历服务。

禁止：伪造用户日程、覆盖个人投递数据、提交私人备忘录或密钥、仅以预览截图宣称桌面版已上线。

### 已知边界

- 这不是闹钟服务：关闭程序后不会主动发系统提醒、短信或邮件；不接第三方日历。
- 小窗读取固定本地 18765 服务，最多缓存 30 秒。服务未启动时明确显示未连接；本次不改旧版启动器，也不自动启动另一套服务。
- 旧 Python 台账与 TS profile 的投递数据是历史上独立的，两者没有在本次自动迁移或合并。日程只存在 TS profile，小窗读取同一日程接口。
- 未强制关闭用户正在使用的小窗；旧窗口刷新／重开后的原生视觉验收尚需执行。浏览器交互、Python 桥接测试和实际只读连接均已通过。
