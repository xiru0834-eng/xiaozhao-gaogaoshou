# 网页版工作台：细节优化与验收

日期：2026-09-21（悉尼）

## 本轮目标与边界

针对网页版工作台改善信息层级、可见公司数量、小窗口操作和模块一致性。延续「薄荷石墨·轻量工作台」与现有五位角色，不重绘角色、不改公司资料、投递状态、接口、数据库结构或后台流程。本轮没有安装新依赖，也没有提交或推送 Git。

使用 Impeccable 的产品化与精修方法：减少重复信息、明确主次操作、角色装饰让位于任务内容；分别由视觉、模块交互、浏览器验收三个 agent 工作，主 agent 整合和复核。

## 已实现

### 1. 工作台导航

- 将机会清单、面试日程、每日更新、岗位更新、模型设置整理为五个固定入口；宽屏在左侧，小窗口为顶部紧凑导航。
- 顶部保留连接状态、换肤、明暗模式、导出备份，不再把所有模块按钮挤在一起。
- 移动既有按钮而不是复制按钮，保留原事件和未保存修改保护。取消离开模型设置时，页面和导航选中态均不改变。
- 每日更新计数只更新文字节点，不覆盖导航图标。
- 为模型入口补上稳定 ID，使既有“前往模型设置”关联入口能够找到按钮。

### 2. 机会清单

- 压缩角色横幅、统计和状态筛选；提供“收起概览”，不改变筛选与投递记录。
- 公司卡片按公司、岗位、城市/截止、推荐码、进度/入口排序。根据工作区宽度显示 1–4 列；保留紧凑清单。
- 删除重复的关键词装饰行，不删除原岗位文本；长标题与完整信息仍可通过公司详情查看。
- 手机隐藏重复截止横幅，仍保留“7 天内截止”的统计入口与分组。
- 筛选、排序、导出浮层限制在视口内；可滚动、可 Escape 关闭。定位仍以各自 details 为锚点，不能将 details 改为 static。

### 3. 各模块与弹层

- 统一模型配置/试用、岗位更新、每日更新、日程、邮箱、换肤与任务表单的文字、控件、间距和语义色。
- 日程长表单滚动由 form 承担，标题和保存区保持可见；避免 Chromium 下 fieldset 内部匿名布局导致无法滚动。
- 邮箱、换肤浮层采用固定标题/操作区和可滚动正文。
- 保留加载、禁用、错误、未配置等原有反馈，不把未完成操作显示为成功。
- 五主题继承同一套布局；键盘焦点、触屏 44px 热区、减少动画偏好、小窗口断行得到统一处理。

## 验收口径

| 项目 | 验收要求 |
| --- | --- |
| 首屏密度 | 1366×900 默认卡片布局完整显示 6 张；390×844 能看到完整第一张 |
| 浮层 | 筛选、排序、导出不越出视口，不透明背景，不与底层内容重叠 |
| 导航 | 五入口可达；模块返回恢复焦点；未保存修改取消离开时保持原页 |
| 筛选 | 搜索、别名、性质、状态、推荐码、最近新增组合仍有效；空结果可恢复 |
| 换肤 | 五角色 × 明暗主题可读、无破版；取消换肤不保存临时选择 |
| 小窗口 | 1366、1024、768、390 宽度无文档横向溢出；状态条允许局部横向滚动且末项可到达 |
| 数据保护 | 不向真实状态接口发送写请求；前后 applications 行数和有序数据哈希一致，完整性 ok |

- TypeScript 类型检查通过。
- 完整 Node 测试：234 通过，0 失败；其中新增 3 项导航契约/未保存保护测试。
- 浏览器使用独立 Edge 会话。`scripts/verify-web-polish.mjs` 用明确标记的合成公司验证筛选，模块使用本机只读响应；阻断所有非 GET/HEAD 及外域请求，不调用付费模型或邮箱服务。
- 第一轮正式浏览器自动检查 66/66 通过；人工截图复查仍发现排序浮层透明，因此不把这轮结果视为最终视觉放行。已要求修复并增加“不透明背景”回归检查，最终结果在文末记录。
- 真实 315 家公司目录只读截图：`artifacts/qa-web-polish/live-{1366,1024,768,390}.png`。390 宽度首家公司标题在约 y=569，首卡完整可见。
- 日程手机表单实测可滚动至最后字段，标题、保存栏保持可见；邮箱/换肤对话框无横向溢出。
- 两个数据库检查前后完全一致：TypeScript 预览 `applications` 1 行；旧版安装目录 159 行。两个都是 `integrity_check=ok`。两者本来就是独立资料目录，不能将预览统计误当旧版记录丢失。

## 保留的验证边界

只构建前端 `dist/web`，没有重新编译、重启或升级后台。18765 当前后台仍对“邮件转求职任务”显示需要重启的提示，该入口实际编辑路径不能在此服务验证。任务表单样式覆盖不等于该后台功能已交付。本轮不将邮件接入、模型真实生成、求职任务写入或安装包兼容性计入通过。

由于当前仓库已有大量并行改动，整仓 Git diff 不代表本轮范围。回滚本轮时只处理工作台导航、上述表现层样式及对应小改动，不覆盖其他已存在的源码和用户数据。
