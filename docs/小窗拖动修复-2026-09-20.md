# 小窗拖动修复

## 问题与证据

用户反馈原生「校招高高手」浮窗不能拖动。安装版 `launcher.log` 中，拖动调用从 WebView2 的 `pywebviewMoveWindow` 进入 WinForms `move()` 后持续报错：

```text
ctypes.ArgumentError: argument 5: TypeError: 'NoneType' object cannot be interpreted as an integer
```

`floating_native.py` 给进程共享的 `ctypes.windll.user32.SetWindowPos` 设置了严格整数参数类型。pywebview 使用同一个缓存函数对象，移动窗口时以 `SWP_NOSIZE` 标志忽略宽高，并传入 `None`；于是调用在参数转换时失败，根本没有执行窗口移动。

## 修复范围

- `floating_native.py` 改为独立的 `ctypes.WinDLL('user32')` 对象，保留本应用严格的原生参数声明，不污染 pywebview 的函数对象。
- `companion.py` 的定位、DPI、鼠标状态读取统一使用这个独立对象，不再修改共享对象。
- 不修改第三方 vendor、HTML/CSS、固定/自动收起策略、后端接口或数据库。
- 不增加依赖，不改变投递状态和今日计数规则。

## 验收与结果

1. 新增 `test_native_bindings.py`，在全新子进程中检查导入副作用和参数兼容性。修复前 3 项全部失败，其中一项复现日志中的同一错误；修复后 3 项全部通过。
2. 模拟 pywebview 的原生调用参数，覆盖 100%、150%、200% 坐标比例及负坐标。使用无效 HWND=0，不创建或移动任何窗口。这是参数兼容性验证，不是跨屏实拖验证。
3. `python -X utf8 -m unittest -v`：73 项通过，包括拖动期间不自动收起、固定/编辑/保存失败保护、持久化与启动检查。
4. 已将两个运行文件同步到安装目录，实际运行路径与常规 LocalAppData 路径的文件哈希一致；新进程导入安装版后的拖动参数回归验证通过。
5. 更新前后 SQLite `PRAGMA integrity_check` 均为 `ok`；128 条状态记录及所有记录内容摘要一致。
