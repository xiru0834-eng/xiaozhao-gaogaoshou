# 桌面统一升级与桌宠接入

本文记录 Python / TypeScript 桌宠接入的历史实现与验收。相关代码现位于 `products/legacy-desktop/`，当前命令见 [兼容工具说明](../products/legacy-desktop/README.md)；完整的校招与面试桌面应用见 [Electron 版](../products/shizhi-desktop/README.zh.md)。

## 目标与范围

把“桌面快捷方式 → 最新 TypeScript 服务 → 同一份真实投递记录 → 悬浮助手／完整工作台”接通，接入已经生成的五位桌宠，不重画角色、不重新设计主页面。

桌宠第一版提供透明窗口、待机眨眼、招呼、拖动、位置记忆、五角色切换、暂停动画、打开悬浮台账／完整版／日程和退出。暂不生成缺失动作，不承诺角色动画已达最终逐帧质量，不启用收费 API、邮箱同步或自动投递。

## 已核查现状

- 旧正式台账 18763 与 TS 预览 18765 是不同资料，存在进度冲突；具体个人状态不随源码发布。
- 冲突策略由资料所有者确认：以正式资料为准，预览不覆盖正式记录。
- 18765 运行的是旧后端；不终止这个曾被策略拒绝停止的进程。新桌面资料及服务使用独立固定端口 18766，旧预览仍原样保留。
- 桌宠现有 70 帧素材和清单未集成。Windows 下 pywebview 不支持透明窗口，因此桌宠采用 Win32 分层窗口显示 RGBA 帧；业务仍由 TypeScript 服务负责。

## 实现顺序

1. 数据与服务基础：使用已有只读快照导入器将旧记录迁入新 `desktop-primary` 资料；迁移前确认冲突处理，禁止合并覆盖旧库。启动器验证应用、资料身份和新版能力；端口冲突明确报错。
2. 悬浮助手桥接：复用现有紧凑界面和拖动／保存保护，用 TS API 读取目录、保存状态，完整版和日程均打开同一服务。图片走受控本机资源，不再内联超过 WebView2 限制的图片。
3. 桌宠外壳：仅负责原生显示、动作、拖动和入口，不存第二份投递记录；帧按 manifest 时长播放，退出释放 GDI 资源。
4. 隔离验收：临时资料完成保存／重启、原生启动、桌宠显示、透明边缘、拖动和入口验证，再备份快捷方式并切换。

## 文件和边界

- 新增 `desktop_runtime.py`、`desktop_client.py`、`desktop_companion.py`、`desktop_pet.py` 及相应 `test_desktop_*.py`；Python 仅为已有 Windows 外壳与启动桥接，数据及核心业务仍在 `src/` 的 TypeScript 中。
- 新增 `assets/pet/`，只复制 manifest 与实际 PNG 帧，不包含无关原始素材、简历或密钥。
- `companion.py` 只增加可注入 HTML 的入口，保留原版路径；新版入口不会打开 18763。
- 保持当前脏工作区及其他修改，不重置、不提交他人改动。
- 独立资料不放源码目录，不覆盖或删除任何旧数据库，不复制凭据到 Git。
- 旧版保留作回退；切换后再在旧版修改会产生分叉，不承诺双向同步。

## 验收标准

1. 新入口健康检查必须识别最新 `recruitmentTasks` 能力与固定 profileId；不同服务／不同资料／端口占用均拒绝，不写错库。
2. 迁移的每条公司、状态、原更新时间完全一致；旧库哈希及完整性不变。重跑导入拒绝覆盖已有进度。
3. 新小窗与完整网页共用同一服务：临时测试公司保存后网页可读，服务重启仍保留。
4. 桌宠 PNG 透明窗口可见，拖动超过阈值不误触打开台账，位置不会永久丢到屏幕外；五角色能切换，暂停不消耗动画帧，退出释放资源。
5. 双击桌面入口能启动／复用服务，不依赖手动开终端；失败写日志并提示，不出现无说明的黑窗。
6. 原生验收不编辑用户真实投递进度；测试使用隔离目录。

## 命令

```powershell
npm run build
npm test
python -X utf8 -m unittest -v test_desktop_client test_desktop_runtime test_desktop_pet
python -X utf8 -m unittest -q
pythonw desktop_runtime.py
```

沿用 Python snake_case／TypeScript typed functions；仅本机 HTTP，禁止跟随重定向、连接外部地址或把错误响应当作已保存。测试先覆盖失败路径再接实际服务，浏览器使用隔离配置。

## 参考

[pywebview 官方 API](https://pywebview.flowrl.com/api/) 明确 `transparent` 不支持 Windows。Win32 分层窗口实现以 Microsoft `UpdateLayeredWindow` 文档和本机原生验证为依据。

### 仍有边界

- 这是本机桌面接入版，不是已验证干净电脑的安装包，也未推送 Git。
- 角色素材仍为现有动画样片；招呼动作有已知帧间差异。此次没有重画或补齐探头、落地等动作。
- 桌宠角色、小窗和网页皮肤分别选择；没有跨窗口联动换肤。
- 已做本机透明显示和拖动处理验收，未做人手多显示器、不同缩放、系统睡眠／恢复的完整矩阵或长期资源基准。
- 双击桌面入口会启动／检查后台；退出桌宠不会关闭后台。没有新增开机启动、收费调用或自动邮箱授权。
- Node SQLite 仍有实验性提示；当前版本号仍为工程版 0.2.0-dev，以固定安装快照和健康能力核验本次部署，不宣称自动在线升级。
- 当前检索和邮件能力保持原实现限制；本轮不把 API／邮箱合成测试当作真实账号接入成功。
