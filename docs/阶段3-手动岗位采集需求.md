# 阶段 3：手动岗位采集——需求与验收规格

日期：2026-09-20。状态：**待用户审阅，尚未实现**。对应总路线的第三阶段 C / T09–T12，不是已完成的数据导入子任务 T03。

## 1. 用户能得到什么

在「校招高高手」点击「检查岗位」，选择已支持的官方招聘来源；程序读取公开岗位内容、整理要求和原文依据，列出新增、变化、重复及待确认项。用户检查后明确接纳，才保存到本机目录。原投递进度保持不变。

流程：**选来源与核对求职条件 → 查看本次请求上限 → 检查 → 看岗位及证据 → 选择接纳 → 刷新/重开仍存在**。

先交付一条来源的完整路径，再以至少三家公司真实试点验收。不是本阶段实现全网搜索、每天自动运行、内推全网搜集或自动投简历。

## 3. 功能需求

| 编号 | 功能 | 可验收行为 |
|---|---|---|
| F01 | 最小求职条件 | 本地保存毕业月份、学历/专业类别、岗位方向、地点偏好及应届/实习开关；本人预设为 2027-01、软件工程硕士、AI/Agent/RAG、城市不限。确认后使用，不保存身份证、电话、完整简历。偏好有 revision，运行保存其快照 |
| F02 | 已支持来源 | 只选经过登记的公司官网/官方招聘平台公开职位入口；登记公司/租户、允许域名与路径、来源类型、访问方式和核验时间。未支持网页明确提示，不声称全网检查 |
| F03 | 手动检查 | 明示检查哪些来源、最多几页及模型调用上限；点击才开始。没有模型时可读取来源、看原文和确定性字段，不把它称为 AI 提取完成 |
| F04 | 安全读取 | 服务端读取无需登录的 HTTPS 页面或公开且已验证的结构化接口；记录最终 URL、访问时间、访问结果、正文摘要哈希。验证码、登录、空壳页面、网络错误分别记录 |
| F05 | 岗位提取 | 公司、标题、官方 ID/URL、城市、届别/毕业窗口、学历/经验、技能、薪资原文、发布时间、截止、入口与证据；未知填 null，不用抓取时间代替发布日 |
| F06 | 确定性匹配 | 先核实 AI 岗位方向，再检查毕业窗口/学历/经验；明确不符不得被模型理由覆盖。条件未知进入待核验；实习单列，时长/到岗要求未知不假定可以到岗 |
| F07 | 增量对比 | 分为新增岗位、已有岗位变化、重复无变化、证据不足/不匹配；“首次发现”不等于“今天新开”。同公司新岗位不因公司已投而被隐藏 |
| F08 | 运行反馈 | 可见读取/解析/核验进度，成功、受限、失败、重复和候选数量；任务可取消，刷新后可以重新查看。全失败不能显示“今日无新增” |
| F09 | 差异预览 | 每个关键字段可展开原文片段、链接、核验时间及前后值；有冲突的不能默认选中。未知或不符不能一键变成“推荐可投” |
| F10 | 明确接纳 | 用户勾选候选并接纳；同一次接纳原子、幂等；重复点击/响应丢失后重试返回原回执；冲突不静默覆盖，未选项仍待处理 |
| F11 | 保存和追踪 | 已有公司不复制；新公司仅末尾追加，保持旧顺序/日期；新增岗位与公司关联；变化留历史。重开、备份仍能查询岗位及证据 |
| F12 | 内推保守继承 | 保留既有推荐码/来源，新增岗位只作公司关联，未明确批次和适用范围则标“待核验”；不把旧码当本岗位有效码，不试投、不自动联系员工 |

业务判定必须拆开：

- `availability`：`open`（原页明确可申请）、`closed`（原页明确结束）、`unknown`、`login_required`。邮件投递入口不证明已收到简历。
- `eligibility`：`eligible`、`ineligible`、`unknown`。学历、经验、届别、方向分别保留结果和证据；整体有明确不符就不推荐，未知硬条件就待核验。
- 推荐条件：原页身份可信、关键字段有证据、availability=open、eligibility=eligible 且岗位方向符合。不把模型自报 confidence 当通过依据。
- HTTP 404/403/超时只是访问事实；没有明确招聘结束证据，不改变已有岗位的开放状态。到期但时区/时刻不明只提示“需复核截止”，不猜确切下架时间。

## 4. 非功能需求

| 维度 | 初版约束/指标 |
|---|---|
| 隔离 | 采集器仅拿到目录/候选仓库接口，拿不到个人进度 Store；不能读完整简历或向模型发送个人申请记录。个人库不做 schema 改动 |
| 来源安全 | 仅登记的 HTTPS 域名与路径；DNS 全结果检查、连接固定已核验地址；每次重定向重新检查，最多 3 跳；拒绝内网/回环/元数据地址、URL 凭据、个人申请 token、Cookie 登录态；不执行网页 JS/脚本 |
| 访问规则 | 尊重网站条款及 robots 规则；禁止时跳过，无法确认时保守暂停该来源。robots 不是访问授权；不绕验证码、登录及反爬 |
| 资源上限 | 默认一次 1 个来源，可选最多 3 个；最多 10 个详情页、总 HTTP 请求 20 次（含 robots/重定向）；每域并发 1、间隔至少 1 秒；单请求 15 秒、整个运行 5 分钟、解压后单页最多 2 MiB |
| 模型边界 | 每次检查最多 3 次模型调用，模型并发 1、保留每分钟 6 次限制；默认无自动重试。每页单请求，正文最多 16,000 字符、含模板总输入最多 20,000 字符；超长拒绝并标受限，不能静默截掉硬条件。输出最多 min(配置值,4096) tokens；截断结果不入库 |
| 成本 | 开始前展示调用次数/输入长度/输出上限和“单价未知”；调用前持久化预留，异常中断保留已预留次数。显示服务返回 usage，缺失则未知；取消不承诺免计费，不偷偷加调用修复 JSON |
| 可靠性 | 网络等待不持有数据库事务；接纳事务短小；运行中断恢复为 interrupted，不自动重放付费调用。SQLite 写失败不得留下半批数据 |
| 响应 | 本地创建运行/取消请求 1 秒内返回；固定 315 公司+100 岗位夹具下，核心本地 API p95 <500ms（30 次测量，排除外网时间）；采集期间仍可搜索并保存投递进度 |
| 容量 | 初版最多保留 100 个运行、1,000 份未接纳正文缓存或 100 MiB；达上限停止新采集并提示。禁止自动删除已接纳证据/个人数据；清理能力另行批准 |
| UI | 沿用当前机会卡片与薄荷石墨风格，只增更新中心入口、运行提示和证据侧栏；320/768/1440 宽度可操作、键盘可达、状态不只靠颜色；不再大改主工作台布局 |
| 隐私与日志 | 密钥不进入浏览器持久化、提示词、日志、Git 或目录备份。运行日志记录计数/错误类别/版本；原文仅存本地证据库，日志不复制全文；所有返回纯文本渲染 |

页面读取上限与模型调用上限分别计数：确定性结构化提取可处理已读页面；需要模型但超过 3 次预算的页面标为 `skipped_model_budget`，本次为 partial，并显示未处理数量。不能静默丢弃剩余页面后报告“全部检查完成”。

以上数值是**待实施的初版限制和验收目标**，不是当前已经具备的能力。真接口消费须在用户指定服务和本次额度范围内；没有凭据仍可完成离线工程测试，不冒充真实 AI 验收。

## 5. 数据契约（拟新增）

采用 strict TypeScript 和运行时校验；输入一律 `unknown`，验证后才能参与匹配/写库。

```ts
type EvidenceRef = {
  evidenceId: string;
  field: string;
  quote: string;
  start: number; // 相对于保存的规范化正文，必须可逐字回查
  end: number;
};
type Decision = "eligible" | "ineligible" | "unknown";
type Availability = "open" | "closed" | "unknown" | "login_required";
type RunState = "queued" | "running" | "completed" | "partial"
  | "failed" | "cancelled" | "interrupted" | "needs_configuration";
```

岗位至少包括稳定身份（sourceId+tenantId+externalId，或经适配器验证的 canonical URL）、companyId、title、locations、jobType、graduationWindow、degreeRequirement、experienceRequirement、skills、salaryText、publishedAt、firstSeenAt、lastVerifiedAt、deadlineText/date/timezone、applicationUrl、availability、eligibility、字段证据及版本。

- URL 只按该来源的已知规则规范化，不能通用删除 query 或 hash；招聘页的 hash 可能带岗位 ID。身份键由程序确定，不接受模型改写。
- 同 ID 多城市为同岗 locations；不同 ID 即使同名也分开。跨站疑似同岗只给合并建议，不模糊自动合并。
- `firstSeenAt` 和公司追加序号不可重写；同岗新内容写 observation/history；`publishedAt` 未明确为 null。
- 证据片段存在不等于语义正确；日期范围、最低经验等使用确定性解析，复杂条件冲突标 unknown。
- 新公司若归属/性质无法核验，候选可保留，但不能为了入库默认“私企”。已有四类性质枚举保持兼容；人工确认必要字段后才能创建公司。
- 求职偏好只用于本机规则；模型仅见公开岗位正文与提取模板，不传学校姓名、联系方式、投递状态。运行保存偏好版本，接纳时偏好变化需重新核验。

## 6. 技术可行性与需要补齐的能力

### 6.1 来源层

首个适配器只支持无需登录的职位详情页及官方结构化内容。拟采用标准 HTML parser 提取 `main/article`/受控选择器、明确标识的 JobPosting 数据；不靠正则整页去标签，不抓隐式登录 API。候选依赖为 parse5，实施前确认版本、许可证、供应链和锁文件，当前不安装。

2026-09-20 通过公开网页读取验证了 [Speediance 大模型应用开发工程师](https://sil.speediance.com/zh/career/llm-application-engineer)：页面含职责、要求和投递入口，但明确要求至少 3 年开发经验。适合作为“AI 方向相近却硬条件不匹配”的真实负例，**不能当成适合本人的校招岗**。这是工具访问可读证据，不是尚未编写的 Node 抓取器通过证据；访问规则、Node 直连和其余两家试点仍待 C0 实测。

### 6.2 模型层

保留现有 Chat Completions 非流式协议、HTTPS/DNS 检查、Windows DPAPI 和超时机制。新增仅服务端可调用的 extraction 请求；统一经过 ModelService 并发/限流/版本检查及运行预算。浏览器试聊 2,000 字限制不变，禁止开放一个可任意传模型参数的新后门。

不依赖所有兼容服务都实现 JSON Schema/工具调用；模板要求 JSON，随后严格解析、拒绝多余字段与格式错误。结构化源能直接提供的数据优先程序解析。恶意正文即使影响模型，也没有工具权限、SQL 权限或入库权限。

### 6.3 存储层

拟把 `catalog.db` 升为 v2：增加 sources、jobs、job_observations、evidence、collection_runs、update_candidates、acceptance_receipts。公司仍复用既有稳定 ID、顺序及别名；求职偏好为资料目录独立原子配置。

候选、接纳回执、岗位和新公司在**同一 catalog 连接的事务**内写入；不能把现有单条 append() 当成跨库原子批次。需在存储层提供事务级接纳入口，不嵌套 BEGIN。不同批次接纳同一 jobKey 的唯一约束和 expectedRevision 同时生效。

升级前生成可独立打开的 v1 一致性备份，校验后才事务迁移；未来 schema 拒绝启动。旧二进制不认识 v2，不能声称直接切回旧代码就完成回滚。若回退，只恢复该次升级前的目录快照到新资料，保留个人 `qiuzhao.db` 的后续记录；需说明 v2 后的目录新增不会自动进入 v1。

## 7. API 草案（均未实现）

沿用本机 Host/Origin/令牌/profileId 校验；不改变旧 `/api/status`。新接口错误统一 `{profileId,error:{code,message}}`；外网读取只允许通过登记 sourceId，不提供任意代理 URL 接口。列表 pageSize=20，最大100。

| 接口 | 输入概要 | 结果/关键错误 |
|---|---|---|
| GET/PUT `/api/job-preferences` | PUT: expectedRevision+脱敏条件 | 保存后的 revision；400 VALIDATION、409 REVISION_CONFLICT |
| GET `/api/sources` | 分页 | 支持范围、访问状态、是否可启用 |
| POST `/api/collection-runs` | mode=`source_only`或`extract`、sourceIds、expectedModelRevision（extract必填）、expectedPreferenceRevision（extract必填）、requestId、limits（只能低于服务端上限） | 202: runId+queued；409 BUSY、428 NEEDS_CONFIGURATION；同 requestId+同参数返回同运行，不同参数冲突；source_only 不调用模型、不形成可接纳岗位 |
| GET `/api/collection-runs/:id` | runId | state、阶段、计数、预算、错误类别、候选数；404 NOT_FOUND |
| POST `/api/collection-runs/:id/cancellations` | 无额外参数 | 202/200，终态幂等；不能回滚已接纳数据 |
| GET `/api/update-batches/:runId/candidates` | 分页 | 候选分类、字段差异、证据引用、canAccept；无证据关键字段 canAccept=false |
| POST `/api/update-batches/:runId/acceptances` | candidateIds、expectedCatalogRevision、expectedPreferenceRevision、idempotencyKey | 接纳回执+新增/变化/重复数；409版本/幂等参数冲突；候选非法则整次不写 |
| GET `/api/jobs`、GET `/api/evidence/:id` | 分页/公司筛选、evidenceId | 岗位信息、最小证据正文；只提供当前资料内容 |

POST 接纳只传服务端候选 ID，不允许客户端直接替换候选内容。超过24小时的候选须重新检查来源；接纳时不隐式联网或计费。取消结束后不得继续调用或产生可误认为已接纳的新项。

## 8. 固定评测与硬门槛

**当前尚无阶段 3 评测集或通过分数。** 实施先建立版本化60例，40开发/20冻结，固定 caseId、来源/合成标记、取得时间、许可说明、脱敏摘录、哈希、预期字段和判断理由。同一岗位近重复不能跨集合。冻结集不用于调提示词；看过失败再调参后，原冻结集降为回归，补充未用样本重新验收。

| 场景 | 总数 | 开发/冻结 |
|---|---:|---:|
| 明确匹配 AI 岗位 | 20 | 14/6 |
| 2026届/多年经验/博士硬条件/相邻岗位不符 | 10 | 6/4 |
| 毕业窗口未知、实习到岗未知、登录/动态空壳 | 10 | 7/3 |
| 同岗重复、同名不同ID、多城市 | 8 | 5/3 |
| 明确关闭与网络异常 | 6 | 4/2 |
| 提示词注入、非法结构、无证据字段 | 6 | 4/2 |
| 合计 | 60 | 40/20 |

数据层/网络层故障另有独立测试，不挤占上述60例。首次模板前完成开发集标注，冻结集采用独立人工复核；真实片段权属不足则用标明“合成”的最小样本，报告真实/合成构成，不伪称全是真实招聘集。

门槛：

1. 个人进度零误改；原315公司字段、顺序、既有日期逐项一致；重复接纳零重复；失败零半批写入；备份完整性 ok。
2. 关键事实（公司/ID/入口/届别/经验/学历/关闭证据）无证据确定值为0；网络错误误判关闭为0；跨公司误绑为0；所有推荐均能回查原文。
3. 推荐 precision≥95%，eligible case recall≥80%；冻结匹配6例至少识别5例，推荐分母为0直接不通过。报告 TP/FP/FN 实数、unknown率、排除原因，不把20例小样本当总体置信保证。
4. 对可读取且金标完整样本，非关键字段 micro F1≥95%；日期按规定精度比对、城市集合比对；字段整体置空会丢 recall，不能取巧过关。
5. 固定 provider/model/revision/promptVersion/schemaVersion 记录；真实模型跑冻结集两次，两次都过硬门槛。合成模型仅验工程流程，不能算模型质量分。付费评测独立于普通3次检查预算，先展示最多40次调用并由用户确认，不偷换预算。
6. 至少3家真实官方来源端到端；含至少1个证据完整的匹配正例、1个硬性不符或未知例，不能全部用排除例冒充推荐成功。真实网页失败如实记录。
7. 运行中取消/重启/断网/401/429/写失败、并发接纳、响应丢失重试均有回归；UI在采集时仍能使用台账；悬浮助手门槛单独标记，不以网页替代。

## 10. 依据与决策状态

- HTTP 访问规则依据 [RFC 9309](https://www.rfc-editor.org/info/rfc9309/)，本产品遇到无法判定时采用更保守的停止策略，不把 robots 当访问授权。
- 内网访问与 DNS 风险依据 [OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)，采用登记来源、全地址核验和固定连接地址。
- 原子接纳依据 [SQLite transaction](https://sqlite.org/lang_transaction.html)，保持单目录库事务，不声称多个独立库自动具备联合原子性。
- HTML 解析候选 [parse5](https://parse5.js.org/)；版本/引入尚未决定。Node 保持项目24.x范围，不因最新文档版本更高而升级运行时。

**本轮决策是“可以进入实施准备，不能将第三阶段或真实模型门槛标成已通过”。** 不改程序、数据库、已投状态或定时任务。
