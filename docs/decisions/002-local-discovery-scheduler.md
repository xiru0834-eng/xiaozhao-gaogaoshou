# ADR-002：本地单一执行服务，搜索与模型分离

状态：Proposed，待用户审阅。日期：2026-09-20。

## 背景

阶段3已有受控来源读取、模型提取和候选接纳，但尚无搜索、内推结构化、持久化每日预算与调度。资料由一个进程独占，直接另开定时 worker 会与已打开的工作台冲突。

## 提议

- 复用 TypeScript/SQLite；一个 LocalEngine 持有资料与数据库，网页和定时触发共用 DiscoveryRunner。
- 将 SearchProvider、来源适配器和 ModelService 分离，模型不拥有网络/数据库/预算权限。首个搜索适配候选为 Tavily，真实中文样本效果决定是否采用。
- Windows Dispatcher 只找/启动同用户 engine 并触发到期检查；日期由 IANA 时区策略和持久化日键决定。
- 自动采集、自动接纳、睡眠唤醒各自开关，默认关闭后台和自动接纳；采集永不写个人进度。
- 请求前预算预留；外部消费不确定不盲目重试。公共来源限定权限，不用搜索结果自动打开任意 URL。

## 未采用

1. 仅靠模型提示词实时搜岗：当前接口不具备搜索能力，也不能提供可靠网页证据。
2. 浏览器 setInterval：关闭页面即停止，不能承担系统后台职责。
3. 两个进程分别访问资料：与现有独占锁矛盾，造成启动失败或双写风险。
4. 第一版使用 Redis/微服务/多 Agent：单机负担大，不能解决来源可靠性和预算问题。
5. GitHub Actions 或维护者云端保管所有用户 Key：改变隐私/部署/费用模型；不符合当前每人本地独立运行需求。

## 后果与门槛

要先增加安全 IPC、持久化预算和恢复测试；本地关机不能执行，只可补跑。来源覆盖与真实模型质量必须单独评测；原生助手桥接依然另列，不因后台框架成立而视为完成。设计细节及实施顺序见 [架构与 API 方案](../自动岗位与内推更新-架构与API方案.md)。
