# ADR-003：邮箱通知先成为候选，再确认写入日程

状态：Accepted；用户批准实施，第一版已落地。实际范围及未通过的真实验收见《邮箱日程助手-第一版实现与验收》。
日期：2026-09-20。

## 背景

用户希望 QQ／Outlook 邮件自动识别笔试和面试时间，不确定时提醒并手动补齐。已有本地日程和模型服务，但不能把预约截止、测评开放窗口等一律解释为面试开始；私人邮件也不能沿用公开网页采集的模型传输授权。

## 提议

1. 软件直接接入服务商：QQ 只使用 IMAP 读取，Outlook 使用委托 Graph＋公共客户端。第一版采用 MSAL 设备代码流，分个人 consumers／学校 organizations；原规划 PKCE 回调后续补充，学校禁用设备代码流时不能绕过。无需安装 Codex 邮箱插件。
2. 邮件同步、候选提取、人工批准、正式日程分层；首版不提供模型自行确认入历。
3. 邮件数据放独立 mail.db，正式日程仍在 schedules.db；跨库使用持久化确认意图＋日程同事务唯一回执恢复，不假定多个 WAL 数据库具有断电原子性。
4. 新模块全部 TS，桌面 Python 只适配概览；只读借鉴现有 Windows DPAPI，不把模型设置中的私有邮件用途默认打开。
5. 先做手动粘贴闭环，再接真实邮箱和后台；提前确认 Outlook 注册条件，降低最后才遇到管理员限制的风险。

## 备选与取舍

- 自动把高置信度模型输出写入日历：误判成本高，首版不采纳；模型自报置信度不作为授权。
- 抓取已登录网页邮箱 DOM：依赖页面结构和登录会话，稳定性差，不作为首选。
- 把邮件集中转发给维护者的服务：增加隐私、运营和共享凭据风险，不符合本机个人软件定位。
- 新数据全部并进旧投递库：迁移影响面更大，不采用。

## 后果

用户需首次授权并复核候选，多一步点击换取明确的事实与修改边界。需要实现重启恢复、隐私同意、额度、连接错误和数据清理，不是只加一个模型 prompt。关机期间不保证同步；学校账户受管理员政策影响。
