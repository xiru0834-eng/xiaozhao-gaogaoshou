# ADR-004：持久化每日更新与最多一次角色来信

日期：2026-09-21。

状态：Proposed。用户已批准产品方向及先产出设计，技术契约待实现验证；不是发布记录。

## 上下文

用户要求软件不依赖Codex、用个人API每日更新岗位和内推信息，并由现有二次元角色在可设置的时间一次性提醒。当前模型调用和有限来源采集存在，但搜索适配、岗位定时、持久日报及一次性提醒尚未接入。已有邮件timer不能证明本需求完成。

资料已有SQLite独占锁，多个网页共享同一个用户资料；进度库必须免受采集写入。用户明确要求保留历史顺序和真实反馈。

## 决策

1. 单一LocalEngine协调搜索、核验、候选/接纳、日报、timer。Windows dispatcher只负责安全唤起/检查到期，不独立写数据库。
2. 用IANA当地日键领取每日运行，timer只负责唤醒。运行、预算和报告持久化，重启不清预算或重复发请求。
3. 新增运行/日报/通知表放catalog.db，终态与通知outbox同事务。qiuzhao.db个人状态无采集写权限。
4. DeepSeek官方搜索作为首个提供者；不同于既有Chat Completions，通过真实搜索结果块提供线索。模型不能自选外发主机或把自述当搜索证据。
5. 收集与收录分开。默认待确认，可信新增自动收录是质量门槛后的独立授权；内推来源声明不能被提升为试投验证。
6. 后端事务领取通知日名额，选择at-most-once自动展示；多窗口仅一个领取。展示后崩溃可能漏看，以持久未读列表兜底，不在刷新后反复打扰。
7. 角色语句本地模板化，数字来自事实回执。复用五套已认可皮肤；隐藏角色不等于关掉提醒。
8. 用户设置的是更新开始时间，提示要等日报就绪；可选固定提醒时间也不能早于结果就绪。无窗口时保留未读，不伪造桌面原生通知能力。

详细契约、边界、实现切片和测试见[主设计](../每日更新与角色来信-详细设计.md)。本ADR补充ADR-002，不废弃其网络/单一拥有者/来源边界；将其候选搜索提供者路线调整为先验证DeepSeek原生适配。

## 考虑过的替代方案

| 方案 | 不采用的理由 |
|---|---|
| 浏览器setInterval每24小时调用 | 关闭页即丢失；后台节流；夏令时、重启和多标签重复无法由它保证 |
| localStorage存“今天看过” | 浏览器、资料和窗口边界不一致；清缓存即重复；只能用于外观偏好 |
| Windows任务直接另开采集worker | 与现有资料独占冲突；容易两套预算和并发写入 |
| 每次看到消息再确认，没确认就重发 | 可能确保最终看到，却违背用户一次性提醒要求 |
| 模型直接输出最终日报并写表 | 计数/时间/内推有效性无法确定；引入提示注入和写入权限风险 |
| 所有搜索结果自动新增公司/推荐码 | 搜索结果没有可靠日期、归属、届别和开放性保证 |
| 做成Codex新的每日自动化 | 依赖本产品会话，不能随Git项目交给其他用户独立运行 |
| 重做桌面原生角色悬浮窗 | 扩展到安装/窗口管理，当前不是最小完整网页版交付；需另验收 |

## 后果与风险

- 会增加状态表和测试，但可解释真实运行、费用、未读及重复请求。
- 最多一次展示不能同时保证浏览器崩溃时用户必然看到；界面明确历史未读可查。
- 本机必须具备运行环境与凭据可用的用户会话。关机或注销时不承诺执行，云端另立方案。
- 仅有一次搜索连通性不能开启大规模自动收录；真实岗位和内推质量必须独立验收。
- 初次发布保留默认关闭和界面显式启用，不从历史聊天自动提取密钥写入长期配置。
- 原安装、旧自动化、邮件状态及个人进度不静默迁移；生产切换与回滚另做检查点。

## 接受条件

固定时钟/重启/并发/预算/网络未知消费/多窗口提醒测试通过；真实中文来源质量报告可复核；至少两次真实定时执行；UI明暗及窄屏检查；个人状态逐条保持且数据库integrity_check=ok。未达标保持对应能力不可启用或明确标识阶段限制。
