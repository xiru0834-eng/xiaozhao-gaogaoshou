## 维护者发布流程

1. 在分享仓库独立修改或同步已脱敏的源文件；不要覆盖整个目录。日常应用的自动收集流程目前不向这里自动发布。
2. 公司新增保持末尾追加；不要重排历史公司或改写别人本机的状态。核实后可以更正公共说明。
3. 跑测试，检查 `git status --short`、暂存差异与文件清单，确认无数据库、简历、凭据和个人备注。
4. 仅提交相关源码、文档、公开数据及测试，再推送 `main`。协作者通过 `git pull --ff-only` 获取。
5. 对更新涉及的重启要求、数据格式兼容性和已知问题作说明。没有做干净电脑测试时，不能声称所有电脑均可直接使用。

## 验证标准

- 新用户初始化得到空数据库；保存一条临时测试进度、重新初始化后仍保留，SQLite 完整性为 `ok`。
- 数据库、缓存、备份和简历命中忽略规则，且不在暂存/跟踪文件内。
- 分享目录没有维护者专属路径、个人资料填表要求和已知私人 URL 参数。
- 初始 315 家公司名称与顺序保持一致，允许后续追加；此前依赖维护者本机备份的测试改为可移植的名称顺序摘要检查，不再因缺少私有备份跳过。
- 启动、筛选、保存失败重试、状态恢复、今日计数、悬浮交互等既有测试继续通过。

## 已知边界

这是源码版，不是签名安装包；当前只验证本机 Windows 环境。悬浮助手需要额外运行环境。尚无自动拉取或热更新，不共享个人进度；关闭浏览器不会关闭后台服务。固定本地端口意味着同机多副本不能作为互相隔离的账户使用。

分享快照内的招聘信息未在本次逐条重新联网验证；不得将所有记录声称为当前可投岗位，公开推荐码也不代表已实测有效。面试/笔试日历备忘录不在本次交付范围。

## 本次验证结果

Windows、Python 3.13.15、Node.js 24.14.0 下运行 `python -X utf8 -m unittest -v`：70 项通过，0 跳过。包含临时数据库从空白初始化、保存与重开后数据保留、`PRAGMA integrity_check=ok`，以及独立子进程的冷启动、健康检查与 HTML 响应测试。

另从已提交的本地仓库重新克隆到临时目录，再运行完整测试：同样 70 项通过，0 跳过；测试后 Git 工作区保持干净。该复核证明测试不依赖维护者的私有备份和未提交文件，但仍是同一台电脑上的克隆验证。

发布检查基于显式暂存的文件清单；真实个人数据库未加入分享目录。文本统一使用 LF，避免不同 Git 换行设置使后端文件摘要测试在新克隆中产生误报。这些结果不等价于已在朋友的干净电脑上完成 WebView2 和悬浮窗口验收。
