## 先失败、后修复的场景

| 场景 | 原问题 | 修复后的验收 |
| --- | --- | --- |
| 1. 疑点数量上限 | 输入 20 项疑点后系统追加提示，保存的数据再次校验却超限。 | 系统生成提示单独识别，20 项人工疑点可往返；人工疑点上限不放开。 |
| 2. 仅日期截止 | 截止只有日期时，没有精确时间戳，允许计划到次日。 | 同时区按已知日期比较，次日拒绝；不擅自补 23:59。 |
| 3. 跨时区截止日 | UTC 当晚实际已经是北京时间次日，原逻辑仍放行。 | 将已知时刻换算到截止日的时区后比较。未知时区不猜测。 |
| 4. 仅日期参加窗口 | 可把计划排在开放前一天或关闭后一天。 | 检查开放日／关闭日，超窗拒绝。 |
| 5. 限时测评 | 要求截止前完成、已知 90 分钟，但 18:00 截止仍能安排 17:30 开始。 | 即使未填计划结束，也校验已知时长；start_by 的“开始前截止”仍允许相应情况，不混用规则。 |
| 6. UTC 偏移 | UTC 正则把 UTC+8 当成 UTC，日历可能差 8 小时。 | 明确偏移不再认证为 UTC；缺证据时置时区待核实，不自动更换用户时间。 |
| 7. 日期和时刻拼接 | 旧面试日期与改期后的时刻分别存在于原文，组合却不是原通知中的场次。 | 日期和时刻必须属于同一引用的同一日期段；失败降为时间待定。 |
| 8. 模型停止后再调用 | dispose 后还可解密密钥并再次调用上游。 | 在进入配置／凭据与网络前拒绝新工作；本测试凭据读取和请求次数均为 0。 |
| 9. 取消后迟到授权码 | Outlook 取消授权后，回调仍能把状态改回 waiting 并显示授权码。 | 已取消请求不再更新授权 UI 状态。 |
| 10. 取消与加密竞态 | 获取授权成功、凭据正在加密时取消，完成后仍写账号并显示 connected。 | 加密之后、同步写库之前再检查取消；账号数为 0，保持 cancelled。 |
| 11. 邮箱服务停止 | 关闭后仍能新建 QQ／Outlook 客户端，或读取凭据。 | QQ、Outlook 和 fetch 入口都拒绝；解密后也复查关闭，避免迟到网络工作。 |
| 12. 模型损坏拖垮邮件 | 配置文件损坏时，读取邮件列表一起报错，无法手工整理。 | 模型错误作为非敏感状态返回；本地邮件、人工候选和已有任务仍可访问。 |
| 13. 无法撤销授权 | 损坏的模型配置也阻止关闭邮件分析授权。 | 撤销不再依赖模型读取；enabled、automatic 都变 false。启用仍严格核验当前服务。 |
| 14. 旧邮件接口绕过校验 | 兼容旧日程的单事项抽取仍接受错误时间组合／时区。 | 新旧分析共用时间证据规则；无证据的日期、时刻、时区保留为空／待定。 |

复现位置：`tests/backend-accuracy.test.ts` 14 项，`tests/mail-providers.test.ts` 新增 3 项。授权测试使用模拟 MSAL 结果和可暂停的合成加密器，没有真实账号登录。

新增正向保护包括中文完整日期、UTC／UTC+08:00、多个明确场次、同日时间范围、独立引用不能拼接，以及 HTTP 拒绝非法计划不写库、重启后原任务保留、仅日期日历标记没有虚构精确时刻。

## 设计取舍

- **精度不升级**：日期不是时间戳；跨时区只在信息充分时比较，时区未知继续提示核实。
- **模型是建议者**：证据规则是保守筛查，不能证明完整语义正确。仍要人工核对来源、改期目标和事项类别；未确认不写正式任务。
- **取消阻止持久化**：允许加密已开始的计算结束，但取消后不得落库。未引入删除账号来“补偿”取消，避免误删原有账号。
- **可选服务失效不封锁本地资料**：模型配置错误不应导致邮箱列表、手动任务和撤销授权一起不可用。错误提示不泄露密钥或配置内容，也不自动重置文件。
- **兼容接口同一规则**：抽取证据工具放在 `src/server/mail-time-evidence.ts`，避免旧接口保留可绕过的时间判断。
