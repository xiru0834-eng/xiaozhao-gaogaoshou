## 信任边界与技术选择

- 外部页面、模型响应、浏览器请求都是不可信输入。HTTP Host/Origin/令牌/资料身份沿用现有约束；来源只接受登记 ID，不开放任意 URL 代理。
- 岗位字段只接收原文逐字片段，公司/URL/身份由来源适配器确定；模型没有进度库、SQL、文件系统或工具调用权限。
- HTML 使用 parse5 8.0.1，robots 使用 robots-parser 3.0.1；两者 MIT，安装前核对包名/脚本，锁定版本并 `npm install --ignore-scripts`。本轮安装审计 0 已知漏洞。依据：[parse5](https://parse5.js.org/)、[robots-parser](https://github.com/samclarke/robots-parser)。
- 原有公网 DNS 全地址检查复用，连接固定已验证 IP；新增来源地址/重定向登记限制，解压前后均限 2 MiB，正文超限不截掉硬条件。robots 404/410 按无资源处理；401/403/5xx/返回HTML不能当允许。

### 回归中发现的旧测试时序问题

首次全量 62 项中旧模型取消用例失败：两次 100ms 取消时只有一次请求到达服务。单独运行通过；根因是把机器调度速度当成业务契约。改为等待实际 request 事件后分别触发超时原因/取消，并等响应连接 close，仍断言无重试；独立真实 10 秒超时测试保留。随后 66 项全通过。没有放宽产品超时。

### 补出的失败用例及修复

1. 实际速境页面的 h1 在 main/article/header 内；统一删除 header 会误删岗位标题。先增加失败测试，再只剔除页面级 header，保留正文内语义标题。隐藏标题、脚本和隐藏投递链接仍排除。
2. 注入运行记录保存失败后，API 可能持续呈现 running。现在后台停止请求、内存返回明确 failed 状态，后续新任务拒绝；重启将未结束的持久化记录标 interrupted，不补跑。
3. 浏览器中的原生确认弹窗干扰测试操作，收录确认改为页面内两步确认；先展示岗位清单，再点击「确定收录」，没有省略用户核对。
