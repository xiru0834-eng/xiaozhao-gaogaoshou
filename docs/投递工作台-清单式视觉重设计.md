# 投递工作台：清单式视觉重设计

## 目标与边界

本轮仅重做 TypeScript 预览（18765）的公司工作台。延续「薄荷石墨」配色与角色品牌，重点改善信息密度、对齐与筛选便利性。旧版 18763、公司目录、投递状态、数据库、模型接口不改。

截图问题：标题、筛选卡片占据过多首屏；状态筛选离列表远；逐行重复核验提示和表头；默认按钮过重，阅读层次不够清晰。

## 实现方案

1. 取消大筛选卡片，改成紧凑页标题、状态页签、搜索工具条和轻量结果栏。
2. 公司性质、行业、国企渠道收入一个可展开的筛选面板。已选条件仍可见、可单独移除，不因收起而失效。
3. 用户反馈「仍像普通后台、没有特色」后，将默认视图调整为双列机会卡片：公司与岗位在顶部，城市/截止居中，公开推荐码与投递操作集中在底部。宽屏三列、小窗口单列。保留 52px 起的紧凑清单，可在「视图」中切换；详情通过公司名打开，取消逐行重复的「核验说明」。
4. 截止分组用温和背景与文字提示，不使用彩色侧边条。分组可收起；保留紧凑视图和明暗主题。
5. 视口较小时重排工具栏和公司行，不通过缩小文字硬塞。保留键盘焦点、语义标签与 reduced-motion。

## 验收

- 实际窗口 1056×898 下对比：改前第一条公司从约 y=376px 开始、默认行高 78px，完整可见 6 家。第一版清单压缩方案随后按用户反馈改为卡片方案，最终验收以首张卡片 y≤300px、完整可见至少 8 家为准；紧凑清单另保留更高密度。
- 320 / 768 / 1024 / 1440px 无整页横向溢出；弹出的筛选、详情不被裁切。
- 组合筛选、清空条件、搜索、排序、分组折叠、密度切换、公司详情、推荐码复制、模型设置往返正常。
- 自动测试、类型检查和构建通过；进度写入测试仅用隔离资料目录。实际资料只读核验不改投递记录。
- 记录真实截图与测量结果，不将静态源码检查当成浏览器验收。
