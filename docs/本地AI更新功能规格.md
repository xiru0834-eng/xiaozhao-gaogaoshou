# 本地 AI 岗位更新：功能规格草案

日期：2026-09-20。状态：AI 更新功能仍为待实现；已按用户选择调整为 TypeScript 路线。工作台和状态存储的 TS 基础迁移已完成，详见 [迁移记录](TypeScript迁移.md)，不代表下文 AI 能力已交付。

## 1. 目标与已确认边界

通过私有 Git 仓库分发应用，获邀用户在自己的 Windows 电脑上独立配置求职偏好、模型与搜索服务，定时发现和核验公开招聘信息。无需依赖维护者的电脑、账号、Codex 安装或中心采集服务器。

技术选择：Vite + 严格 TypeScript 前端、Node.js + TypeScript 后端、SQLite，不更换已认可的 UI 风格。先支持一个 Windows 用户、一个活动求职配置。旧 Python 桌面外壳暂留回退；新增业务不再写 Python。桌面原生窗口方案单独验收。模型厂商、搜索额度与实际付费预算尚未确定，不影响先做离线基础。

成功体验：首次配置 → 测试连接 → 点击检查 → 看见有来源的变更预览 → 确认入库 → 重开仍在；随后主动开启每日任务，可自动采集，并选择是否自动接纳经验证来源的合格新增。

不做：自动投递、自动发送消息、读取短信、绕过登录/验证码、共享个人进度、云端账号系统、无人监督的网页任意操作、自动拉取并执行最新源码。笔试面试日历另立后续需求。

## 2. 当前代码基线

- `src/server/http.ts`、`store.ts`：TS 本机 HTTP 服务，兼容 `applications(name,status,updated_at)` 表及 `/api/status`、`/api/backup`。`app.py` 保留旧版回退。
- `src/shared/catalog.ts`：从旧 `index.html` 提取 `DATA` 和 `APPEND_DATES`，315 家公司及原顺序不变。TS 工作台入口为 `web/index.html` 和 `src/client/main.ts`。
- `floating_model.py`、`companion.py`：悬浮助手直接解析同一 HTML 的目录，保存通过现有 HTTP 接口。
- `launcher.py`：旧版端口 18763、旧实例识别方式。新 `src/server/main.ts` 使用独立端口 18765 与资料目录，不复用旧服务；完整资料身份/导入方案仍待实施。
- 新版基础测试 12 项、旧版回归 70 项通过；严格 TS 构建及工作台浏览器检查通过。不是 AI 更新功能验收结论。
- 原 Codex 每日任务仍针对维护者的日常安装目录，未连接本仓库；本计划不更改该任务。

## 3. 数据与升级边界

拟将运行时资料放在 `%LOCALAPPDATA%\XiaozhaoGaogaoshou\profiles\default\`，不放在 Git checkout。通过显式测试参数支持临时配置目录与独立端口。路径必须由同一运行配置解析，禁止模块各自猜目录。

| 文件/数据 | 用途 | 写入权限边界 |
|---|---|---|
| `qiuzhao.db` | 兼容原公司级投递进度；后续新增岗位级进度表 | 仅用户操作的进度服务写入；采集器不能写 |
| `catalog.db` | 公司、岗位、证据、推荐码、候选变更、采集运行记录 | 经格式/规则核验后事务写入 |
| `settings.json` | 求职偏好、时区、服务地址、限额、调度开关；不含密钥 | 设置服务写入 |
| Windows 用户凭据存储 | 模型及搜索密钥 | 后端使用；前端只得到已配置/未配置 |
| `backups/`、`logs/`、缓存、窗口与活动文件 | 恢复、诊断与本机 UI 状态 | 本地保留；日志脱敏、缓存定量清理 |

首次导入旧台账必须指定来源，使用 SQLite 一致性备份，不删除原目录、不覆盖非空目标。比较快照中的全部公司名/状态/时间及数据库完整性，全部一致才允许切换；失败保持原路径可继续使用。不能仅靠记录条数验证迁移。

旧公司级“已投”不推断为任何新岗位的“已投”。本次第一版继续保留公司级进度；岗位卡片若展示旧状态，必须注明“公司级记录”，不能据此把该公司的新岗位全部过滤掉。完整岗位级投递管理后续单独实施，不做不可逆批量转换。回滚公共目录也不能回滚之后的个人进度。

新公司保持追加顺序和不可变首次发现序号，岗位变化记录前后值；不因抓取失败删除旧行。Git 发布更新种子和代码，不覆盖本机目录、密钥与进度。第一批迁移先在临时数据验证，不操作真实日常安装。

## 4. 最小数据契约

首次建立稳定 `company_id` 与别名；有官方 ID 的岗位用“来源/租户 + 官方岗位 ID”标识。无 ID 时使用经过验证的规范化官方 URL；同名或相似文本只生成待合并建议，不能直接合并。

岗位必备字段：公司关联、岗位名称、岗位 ID 或规范 URL、官方入口、城市、岗位类型/届别、学历与经验要求、毕业窗口、技术要求、原文证据引用、发布/首次发现/最后核验时间、开放状态。未知值明确为 `null`，不从抓取时间推算发布日期。截止时间不明时保留原文，不猜时区和精确时刻。公司同名、跨城市同 ID/不同 ID 均设测试。

证据包含来源 URL、内容摘要、最小必要原文摘录、核验时间和访问结果。模型提取的关键字段必须引用证据；完整个人简历不进入采集流程。

状态分离：`availability`（页面显示开放/明确关闭/未知/需登录）与 `eligibility`（符合/不符/未知）独立。只有页面有可追溯证据才能提高确定性；404、超时、搜索摘要不能独自确认为关闭或可投。

内推信息包含公司、原码/链接、适用批次、岗位范围、发布日期/过期日、来源和核验时间。保留“官方明确说明 / 发布者声称未实测 / 过期或疑似过期 / 待核验”的差别。不得自动试投、跨公司复用，也不抓私人申请会话链接。

所有模型和搜索响应先按结构校验，再进入候选区；未经校验的返回内容不能触发数据库写入或改变任务规则。

## 5. 本机模块与接口方向

在 `src/` 中新增职责明确的小模块，不先引入微服务、消息中间件。以下为后续拟新增模块，不表示这些文件已经存在。

```text
src/server/runtime-config.ts           统一目录、端口、实例身份
src/server/catalog-store.ts            目录种子、稳定 ID、追加顺序
src/server/settings.ts / secrets.ts    非密配置与凭据边界
src/server/model-client.ts             模型协议与超时/额度
src/server/source-fetch.ts             公开页面读取及 URL 限制
src/server/job-extract.ts / job-rules.ts 结构化提取与确定性核验
src/server/update-store.ts / collector.ts 候选变更及有限任务流程
src/server/search-client.ts / discovery.ts 全网线索及来源回溯
src/server/worker.ts / scheduler.ts     单次运行入口与 Windows 调度
seed/                          可发布目录种子；不是个人运行数据
tests/fixtures/                去敏、可重放、标注过的测试样本
```

新增本地接口按资源组织：`/api/settings`、`/api/model-tests`、`/api/catalog`、`/api/jobs`、`/api/runs`、`/api/update-batches`。具体请求/响应与错误示例在对应任务开始前补全，不直接实现未经审阅的接口。

约定：列表分页；开始任务立即返回 `runId`，UI 轮询运行资源而非阻塞 HTTP；入库使用批次 ID 与幂等键；并发修改版本不匹配返回冲突，不做静默覆盖。保留旧 `/api/status` 响应形状，新增接口使用统一错误结构。所有敏感读取、配置变更与外部调用接口均验证本机来源、会话令牌、请求大小及字段；密钥永不回显。

完整工作台与悬浮窗最终必须通过同一目录服务获得新增公司。当前 TS 工作台静态导入 `src/shared/catalog.ts`，后端也提供同源 `/api/catalog` 快照；还未实现动态目录库。旧 HTML 暂留作为独立回退，不能让采集器同时写 TS 和旧 HTML。待动态目录及桌面读取都验收后，再撤销旧读取路径。

## 6. 模型、搜索与采集策略

先接一个明确验证过的云端兼容接口；支持地址、模型名、密钥和连接测试，不假定任何厂商都完全兼容。接口和输出形状不支持时明确报错。Ollama 作为第二种可选适配器，不要求每个人安装本地模型。

模型只理解正文、提取字段、生成有证据的匹配理由；程序负责去重、毕业窗口硬条件、时间、限额、写入、重试。拒绝网页中让代理执行命令、泄露凭据或改变任务的指令。未知条件显示未知，不用模型分数覆盖硬性不符合条件。

先做一条无需登录的官方来源定向读取，证明真实流程，再增加全网发现。首个搜索服务暂选 Tavily 的独立适配器作为可验证方案；正式接入前确认用户可用凭据、预算与国内来源覆盖，必要时仅替换适配器。没有搜索凭据仍可检查配置过的官方来源，但必须标“定向检查”，不能称为全网搜索。

搜索先 24 小时，再按需要扩到 7/30 天；官方来源核验与全网发现分别计数。新公司线索进入发现队列，别名/官网关系核实后追加。搜索摘要只是线索；必须尽量回原始岗位页，不能把搜索引擎生成答案当原文证据。

遵守来源访问规则，限速和有界重试；不绕过验证码、登录或反爬。公共抓取禁止本机/内网/元数据地址、非 HTTP(S) 协议、URL 用户名密码；逐次重定向复核目标。用户显式配置的本地模型地址走独立通道，不与网页抓取的例外混用。

每个运行都记录成功、失败、跳过、范围、消耗与时间。全部来源失败时是失败，不是“今日无新增”；部分失败显示部分完成。模型/搜索额度为上限控制，不把未知单价计算为已知金额。相同内容摘要 + 模型/提示词版本可复用提取结果，但仍重新核验网页状态。

## 7. 自动执行与用户体验

第一阶段只做手动“检查 → 预览 → 入库”。之后增加 Windows 当前用户计划任务，默认关闭，用户可启停/卸载。不持久化 Windows 登录密码。

计划任务按短周期唤起同一单次 worker，由 worker 根据 IANA 时区计算是否到达当天计划；建议默认 15 分钟检查间隔，页面说明不是精确秒级闹钟。支持 `Australia/Sydney` 等时区，覆盖夏令时测试。关机不执行，登录/启动后只补跑一次，不对错过的每一天重复计费。

采用按配置隔离的进程锁、持久化运行状态和租约恢复，避免按钮与计划任务并发双跑。失败重试不重新发布已接纳批次；中断记录不能永久阻止下一次执行。首次模型调用前做配额预留；重试也计入每日上限。

自动入库是单独开关：只有已验收来源、字段及证据完整、无身份/届别冲突的新增可自动追加；其余留待核验。更正关键条件保留历史与来源。采集程序任何模式都不能写入投递状态。

前端沿用现有视觉体系，只补“设置”“立即检查”“更新记录/预览”和轻量状态提醒；任务进行中仍可浏览和改个人进度，不让后台采集卡住主界面。

## 8. 可执行命令与代码约定

现有可执行命令：

```powershell
python -X utf8 -m unittest -q
npm test
npm run build
npm start
```

新增业务测试放入 `tests/*.test.ts`，由 `npm test` 执行；旧 Python 回归单独执行，不能只跑原 70 项来验收 TS。新增 worker、调度和评测命令需实现后同步 README，不把尚不存在的命令写成已可运行。

代码采用 strict TypeScript、命名清晰的小函数、显式依赖注入及参数化 SQL。数据库访问封装于存储模块，不能拼接网页字段成为 SQL。模型返回先以 `unknown` 接收并做运行时校验，不以类型断言代替验证；状态使用明确的联合类型，不靠 UI 文案猜测。

## 9. 验收与权限边界

固定评测：拟建立 60 个已标注用例，40 个开发、20 个冻结验收；覆盖符合条件、硬性不符、条件未知、重复、关闭/网络异常、恶意内容。公开样本只存最小必要且可分享的摘录；合成用例明确标注，不伪称真实招聘页面。

硬门槛：原进度逐条一致；重复导入零重复；网络错误零误关闭；无证据字段不得冒充确定值；所有推荐都有来源；密钥/个人信息零进入日志与 Git；未经授权的本机请求不得触发模型调用/配置变更。高置信推荐在冻结集的精确率目标至少 95%，同时报告覆盖率和不确定率，防止全部拒绝取巧。首批真实来源 3 家证明端到端，扩到约 20 家/至少 3 类来源才评估自动入库；不承诺全网召回率。

Always：先写/明确回归与验收条件，后改实现；对临时数据验证；保留追加顺序、失败日志和回滚路径；两种 UI 均做运行验证。

Ask first：真实模型/搜索的提供者与消费预算、真实数据迁移和切换、注册计划任务、替换已有 Codex 自动化、发布安装包及远端推送。

Never：改写或删除真实旧数据库来“修复”；提交凭据/简历；把网页文本当指令；自动投递；把一次成功或模拟测试描述成长期可靠。

## 10. 官方依据与待验证项

- [Node SQLite 一致性备份](https://nodejs.org/api/sqlite.html#sqlitebackupsource-db-path-options)：迁移采用数据库备份接口而非复制活跃数据库文件；锁定 Node 24.x，关注实验性 API 风险。
- [Ollama API](https://docs.ollama.com/api/introduction)：可选本地模型接入，兼容能力仍需按所选模型实测。
- [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)：搜索独立于推理模型；不在本计划中承诺免费额度、国内覆盖或当前账号可用。
- [Windows 错过时间后启动](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-startwhenavailable)：存在调度条件和延迟，应用仍需自身持久化去重与补跑逻辑。

实施前仅后续联网阶段需要用户选择模型/搜索配置与上限；基础阶段不需要 API Key。跨 Windows 账户、干净机器、WebView2 安装路径和实际站点访问率均待实际验收。
